# DICOM Anonymizer (portable Windows app)

A single `DICOM-Anonymizer.exe` (≈ 2.5 MB) that removes the patient's data from DICOM files. Nothing to install, no
admin rights, no .NET or other runtime, works offline: copy it anywhere (Desktop, USB stick) and double-click it.
Windows 10 and 11 (64-bit).

**Download:** https://amsaleh1998-spec.github.io/Quick-DICOM-Planning/windows/DICOM-Anonymizer.exe
(built from this folder on every push to `main`).

The first time, Windows SmartScreen may say *Windows protected your PC* because the program is not signed:
click **More info → Run anyway**.

## How to use

1. **Add the scans:** drag CBCT/CT folders or DICOM files into the window (or onto the `.exe` icon), or use
   *Add folder…* / *Add files…* (Ctrl+click to pick several). Folders are searched with all their subfolders; file
   names don't matter (`IM000001`, files without extension …).
2. **Output folder:** where the anonymized copies go (filled in automatically: *Anonymized DICOM* next to the first
   scan). **The original files are never changed.** Each scan gets its own new folder (`Case 01`, `Case 02` …), so
   nothing is ever overwritten.
3. **New patient name / ID** (default `ANONYMOUS` / `ANON`), e.g. a case number.
4. Click **Anonymize**. The log lists what was written, skipped or needs a look.

Options (*Keep …*, all off by default): dates and times, patient sex/age/size/weight, study/series descriptions,
institution, device (station name, serial number), original UIDs, private vendor tags. *Rename files and folders*
(on by default) names the output `Case 01\IM000001.dcm` (one subfolder per series when there are several), because
original file and folder names often contain the patient's name.

## What is removed

Based on the DICOM *Basic Application Level Confidentiality Profile* (PS3.15 Annex E), in the main data set **and
inside every sequence**:

- Patient's name and ID are replaced; birth date, sex, referring physician, accession number and study ID are kept
  but emptied (viewers expect them); everything else that identifies the patient is removed: other names/IDs, age,
  size, weight, address, phone, insurance, comments, medical alerts, …
- Every other person name (physicians, operators, reviewers …) – any attribute with a person-name value.
- Dates and times (all of them), institution, department, station name, device serial numbers, descriptions,
  protocol names, comments, request/procedure information, SR content.
- **Private (vendor) tags**, which often repeat the name; overlays and curves (they can contain text); digital
  signatures; the sending/receiving AE titles in the file header.
- Study, series, instance and frame-of-reference **UIDs are replaced** with new ones (`2.25.…`). Within one run the
  same old UID always gets the same new UID, so the slices stay one series and references between files still match;
  the mapping uses a random key per run, so it cannot be reversed.
- *Patient Identity Removed* = `YES` and *De-identification Method* are added.

Kept: everything needed to view and plan – image size, pixel spacing, slice positions/orientation, window settings,
modality, manufacturer and model, and the **pixel data, copied byte for byte** (also compressed: JPEG, JPEG-LS,
JPEG 2000, RLE). Files keep their transfer syntax (implicit/explicit VR little endian, big endian, deflated).

Left out: `DICOMDIR` (an index that repeats the patient's name; viewers read the folder without it) and non-DICOM
files (text, images, viewer programs from CDs …). Damaged files are reported and not written.

Every written file is read back and checked; if the original name or ID still appears anywhere (because of a *Keep*
option) the log says where.

**Limits:** text burned into the image pixels (some screenshots, ultrasound, scanned documents, secondary captures)
cannot be removed by cleaning metadata; the log warns when a file is of such a type. Free-text fields that are kept
by an option may contain names.

## Build

Requires Go 1.24+, nothing else (no cgo). On any OS:

```bash
./build.sh                     # -> dist/DICOM-Anonymizer.exe
go test ./...                  # parser / anonymizer tests
```

`rsrc_windows_amd64.syso` (icon, manifest for visual styles and DPI awareness, version info) is checked in and is
rebuilt from `winres/` when MinGW `windres` is installed. `go build` on macOS/Linux gives a command-line version
(`dicom-anon -out <folder> <files or folders>`, see `-h`); `testing/check_pydicom.py` cross-checks it with pydicom.
`anon/dict_gen.go` (tag → VR, needed for implicit VR files) is generated by `gen/gendict.py`.

| File | Purpose |
| --- | --- |
| `anon/dicom.go` | DICOM reader/writer: element tree with sequences, encapsulated pixel data kept raw |
| `anon/profile.go` | De-identification rules and options, UID replacement |
| `anon/batch.go` | Folders → cases, output names, parallel processing, verification, log events |
| `gui_windows.go`, `win32_windows.go` | The window (plain Win32 API, Windows file/folder pickers, drag & drop) |
| `main_other.go` | Command-line version for macOS/Linux |
